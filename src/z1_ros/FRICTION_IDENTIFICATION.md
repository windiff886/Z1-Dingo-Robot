# 用一个 launch 做关节摩擦辨识

在仓库根目录构建并加载 ROS 1 工作区，然后运行：

```bash
source devel/setup.bash
roslaunch z1_bringup friction_identification.launch
```

这个入口会启动双臂控制器和辨识节点，并复用现有的通信 YAML。启动前，请先关闭 `arm.launch`、`rviz_tcp_test.launch` 等占用相同 MCU 端口的控制入口。**预检通过后，程序会等待 5 秒，然后自动开始实际运动。** 所有参数统一放在 [friction_identification.yaml](z1_control/config/friction_identification.yaml) 中配置，不需要通过 launch 命令行传参。

默认顺序是先测左臂 J1～J6，再测右臂 J1～J6，每次只测一个关节。每个轴做 5 档速度、每档 3 个往返，然后再做正向和反向各 5 次起动测试。测试时，其他关节保持在辨识基准姿态，原有的上下位机增益保持不变。程序只生成辨识结果，不会自动加载摩擦补偿。

## 先选有运动余量的工作姿态

`centers.left/right` 的默认值是空列表 `[]`。这时程序会把启动时测到的六轴位置固定为各臂的辨识基准姿态，整个实验期间不会重新采集或累积更新这个基准。你也可以在 `centers` 中填写经过路径检查的六轴角度，程序会先以低速到达该姿态。程序不会自动回 Home，也不会自动把中心移离限位。辨识区间是中心两侧的 `±amplitude`，默认 `±0.15 rad`；每个被测关节还需要额外留出 `max_tracking_error=0.02 rad` 的余量，也就是说两侧各要有大于 `0.17 rad` 的限位余量。所有选中的关节都会在发出实验目标之前统一预检。

这个入口会强制关闭摩擦补偿，只做关节约束检查，不运行整机避障规划。因此，启动前必须选好一个全段无接触的工作姿态，并保持底盘静止、负载和线缆布置不变。左臂夹爪要保持闭合，不要挂额外物体：当前控制 URDF 按闭合姿态把夹爪约化成固定负载，夹爪编码器与手指模型关节之间的换算还没有标定。

当前默认的六轴配置是：

```yaml
arms: [left, right]
joints: [1, 2, 3, 4, 5, 6]
```

当前 SRDF 的 Home 是 `[0, 0, 0, -0.07435, 0, 0] rad`。在这个姿态下，J2=0 位于控制 URDF 的下限，J3=0 位于上限，因此不能围绕它们做 `±0.15 rad` 的往返运动。所以不要在 Home 直接启动六轴辨识，这个姿态会被运动余量预检拒绝。请先选一个全段无接触、并且有余量的工作姿态。如果只测左臂 J4，可以把配置设为 `arms: [left]`、`joints: [4]`。

## 每轴测完回辨识基准，不回 Home

所有关节都以同一个六轴基准姿态来测试：其他五个轴保持基准角度，被测轴围绕自己的基准角度往返。完成运动摩擦测试和起动测试后，机械臂会返回基准，等运动完成并静置 `settle_seconds`（默认 0.5 s），再准备下一轴。当前程序已经按这个流程执行。

```text
辨识基准 → J1 测试 → 辨识基准 → J2 测试 → … → J6 测试 → 辨识基准保持
```

这样就不会把上一轴的测试终点留给下一轴，也省去了每轴回 Home 再到工作姿态的额外运动。每臂正常测完后会停在各自的辨识基准；如果出现异常，程序会请求 STOP，不会自动回基准或 Home。

## 推荐基准姿态：两臂平行、适度抬肘

按当前整机安装模型筛选出的候选姿态，左右臂都相同：

```text
J1～J6（rad）：[0, 0.8, -1.2, 0.4, 0, 0]
J1～J6（deg）：[0, 45.84, -68.75, 22.92, 0, 0]
```

筛选条件是：底盘静止，云台 yaw/pitch 都在零位，左臂保留闭合夹爪，右臂拆除夹爪，不挂额外物体。安装座、车体、支撑柱和相机来自当前的 `uni_dingo_dual_arm.urdf.xacro`，机械臂运动学和惯量来自控制 URDF；右臂会移除夹爪子树，但不改变 TCP。

当两臂都处于上述基准姿态时，程序用 Pinocchio + Coal 分别检查控制 URDF 的简化碰撞几何和原始碰撞 STL。每次只有一个轴运动，其他轴固定在基准；被测轴按 `0.01 rad` 的间隔扫描 `±0.17 rad`，其中包含计划幅度 `±0.15 rad` 和被测轴的跟踪误差余量。检查时只排除刚性连接件和直接相邻连杆，不套用 SRDF 的 `Never` 排除项。采样结果如下：

| 检查项 | 简化几何 | 原始碰撞 STL |
| --- | --- | --- |
| 双臂之间最小间隙 | 127.4 mm | 102.2 mm |
| 机械臂与车体、支撑柱、云台/相机最小间隙 | 44.4 mm | 31.1 mm |
| 非相邻连杆之间最小间隙 | 14.7 mm | 12.5 mm |

所有测试轴都满足限位余量；把范围扩大到 `±0.17 rad` 后，最小的剩余限位余量是 J2 的 `0.63 rad`。基准 TCP 在整机 `base_link` 系中大约是左臂 `[0.256, 0.117, 1.064] m`、右臂 `[0.256, -0.117, 1.064] m`。这些结果来自离线离散采样，没有包含线缆、现场障碍物、模型尺寸误差，也没有考虑其他关节同时偏移的情况。

**请先核对到达基准的路径，再启用辨识。** 在额外采样的 SDK 低速 Home→基准轨迹中，原始网格在 Home 附近出现了 `link02` 与 `link06` 自重叠，自动转场没有通过碰撞判定。当前 `centers` 仍然为空：请先在现场核对转场路径、实际附件和线缆间隙，再以低速到达候选姿态，最后启动辨识，让程序记录实测基准。运行时仍然只做关节约束预检，不会执行本节的整机碰撞检查，也不会自动避障。

## MCU 决定是否计入夹爪质量

控制节点会先验证配置，再进行被动 MCU 握手，并在构建实际控制器之前读取电机数量：

| MCU 电机数 | 实际配置 | 动力学模型 |
| --- | --- | --- |
| 8 | 六轴 + 夹爪，J2 使用两个电机 | 保留夹爪定子和动子的质量/惯量 |
| 7 | 六轴，无夹爪 | 从同一 URDF 移除夹爪子树及其质量/惯量 |

当前设备应该会自动检测为左臂有夹爪、右臂无夹爪，而不是按左右臂的名字硬编码。六个主关节、限位以及 `tool` 的变换都保持不变。正常控制入口和 RViz 的 SDK 数值预览也采用同样的选择。整机显示和 MoveIt 场景仍由各自的 Xacro 配置提供，本入口不会启动它们。

```bash
rosparam get /left_arm/controller/device_has_gripper
rosparam get /right_arm/controller/device_has_gripper
```

预期结果分别是 `true` 和 `false`。每次实验都会保存实际生效的模型 XML、模型版本、中心位置和控制增益。更换夹爪后，请重启控制器，让它重新握手并加载模型。

## 运动摩擦：正反向、同位置、恒速成对比较

程序通过 `joint_trajectory` 一次提交「加速—恒速—减速」轨迹。速度过渡使用三次 smoothstep，它的位置是四次多项式，现有的五次 Hermite 可以精确复现；过渡时间由最大加速度和 jerk 决定，并保留真实的恒速段。

默认速度档位是 `[0.01, 0.02, 0.04, 0.08, 0.12] rad/s`。程序会按重复轮次交替速度顺序，以减小速度与升温之间的相关性。它用真实接收时间对位置做局部拟合来得到速度，再筛选出实测的恒速段；原始 `dq` 会另外保存。如果出现缺帧、停走、稳态段过短或正反位置区间不足，这一组实验不会参与拟合，原因会写入 `rejected_pairs`。

计算时，先取反馈力矩减去所选模型的重力，再把正反曲线插值到相同的实测位置，然后在相同速度大小处取半差：

\[
F_{\rm pair}(u)=\frac{(\tau-\hat g)(q,+u)-(\tau-\hat g)(q,-u)}{2}
\approx F_c+b u.
\]

共同的重力误差和偏置会在配对中抵消。经过稳健、非负约束的拟合，得到 `coulomb_nm` 和 `viscous_nm_s_per_rad`，它们表示方向平均后的关节等效阻力。前两轮用于拟合，最后一轮用于独立验证；至少需要三个有效速度档。首版不会强行拟合 Stribeck 参数，也不会把方向不对称的阻力与重力偏置解释成可以分别辨识的参数。

## 起动摩擦：缓慢偏移参考，并给偏移量设上限

当 `static_enabled: true` 时，程序会在相同的中心位置和相同的静置时间下，缓慢移动参考来建立驱动力矩。偏移量最多为 `static_offset`（默认 `0.01 rad`），不会切换到纯力矩模式。程序用持续的位置变化来检测起动，阈值取配置下限与静止位置噪声五倍中的较大值。确认起动后，程序发送 STOP，停稳后发送 HOLD，再返回中心。

结果取最初位移之前的反馈力矩残差；把正向和反向的起动力矩取半差，就得到 `breakaway_nm`。如果达到偏移上限仍未确认起动，程序会记录这次没有观测到起动，并把静摩擦结果标为不可用，不会继续增大偏移。这个结果只在指定的静置时间和位移检测阈值下有效。

## 采样和异常停止

辨识入口会打开 `record_control_samples`。每当原生周期收到新反馈，程序就把实际发送的旧输出、反馈和单调时间写入一个有界的单生产者/单消费者队列。ROS 线程会另外计算记录用重力，并发布 `control_samples`；控制线程不写盘，也不做 ROS 发布。

`ControlSample.effort` 是 MCU 反馈，`command_effort` 是主机的前馈字段。`sent_at` 是主机进入本次交换的时刻，`received_at` 是传输层实际读到反馈的时刻；两者都属于主机单调时钟，不是内核发送时间、MCU 采样时间，也不是设备执行确认。V2 协议附带电机温度；V1 的 `has_temperature=false`，温度列不能当作测量值使用。

程序会检测反馈失效或超时、序号缺口、队列溢出、附件变化、其他客户端插入运动、反馈力矩超阈值、跟踪误差超阈值以及非被测关节移动。出现异常时，程序会向已经操作过的机械臂请求 STOP，保留部分数据，但不会自动确认 Fault 或 DISABLE。`effort_limit` 是基于反馈的实验停止阈值，不能代替固件的电流/总力矩限制。

## 输出、查看结果和离线重拟合

每次运行都会创建一个独立目录，默认位于 `~/.ros/z1_friction/日期-时间-编号/`：

| 文件 | 内容 |
| --- | --- |
| `samples.csv` | 十组六轴实测/发送数据（含限幅前的摩擦前馈）、补偿开关、阶段标签、温度、单调时间和反馈序号 |
| `left_model.urdf` / `right_model.urdf` | 实际使用的控制模型，只保存所选臂 |
| `result.yaml` | 参数、配对测量、留出验证误差、拒绝原因、静摩擦试次、配置和模型信息 |

状态可能是 `complete`、`complete_with_rejections` 或 `failed`。每个动态/静态结果都有独立的 `usable`；不要因为实验跑完就直接采用不可用参数。静摩擦试次如果没有起动，对应结果也会被标为不可用。

正常结束时，机械臂会返回中心并保持 Holding，launch 继续运行。按 Ctrl+C 关闭入口后，控制器会按原有的有界停止流程退出，最后发送被动帧。

即使不连接机械臂，也可以重新拟合运动摩擦：

```bash
rosrun z1_control friction_fit.py /完整路径/某次记录目录
```

程序会生成 `result_refit.yaml`，保留现场的静摩擦检测结果，不覆盖原始记录和报告。用不同的速度或另一个姿态复核，再在相同增益下做一次补偿开关对照，是让参数进入实际补偿控制之前的验收步骤。

把可用的运动摩擦结果导入左右臂共享 YAML、重启后加载，以及自动实机 A/B 对照，见[摩擦补偿说明](SDK_ALGORITHMS.md#9-摩擦补偿参数与实机对照)。辨识程序本身不会写活动参数文件，也不会自动打开补偿。

## 离线验证

CMake 测试 `friction_identification`、`friction_runner_offline`、`identification_models_recording` 和 `mcu_udp_loopback` 覆盖以下内容：重力偏差抵消、位置配对、轨迹边界、缺帧和停走拒绝、独立验证、完整采集、起动和重拟合、异常 STOP，以及两种夹爪握手配置。回环测试只访问本机。

在 ROS 1 环境中，`z1_control/tests/ros_topics_test.py` 会检查 Topic、附件模型选择和逐周期采样。物理摩擦参数和实机轨迹的改善需要由实际实验确认。
