# 控制约束审核

日期：2026-10-27。审核以实际故障、算法前提和硬件限制为依据，删除会无依据地阻止正常操作的拦截。范围包括项目自有的 Z1 控制内核、ROS 适配、RViz 测试、标定和通信代码，以及底盘遥控、底盘限制和云台串口相关配置；不修改官方闭源 MCU 库或固件。

## 已删除

| 原逻辑 | 不合理之处 | 当前行为 |
| --- | --- | --- |
| RViz 先要求 Holding，才能发送有限目标 | 使能步骤与明确提交运动目标重复，Disabled 已有实测关节反馈 | 首条有限目标在有效且静止的 Disabled 下从实测位置规划；验证成功后开始运动，失败不使能 |
| 拖动后还必须通过菜单确认发送 | 测试工具将同一目标编辑与提交拆成额外操作 | 拖动松手提交一次，不连续发送 POSE_UPDATE；菜单保留单次重发 |
| RViz 按自己的反馈和模式副本阻止目标及控制操作 | UI 消息滞后、TCP 丢失会拦住控制器本可接受的请求 | 控制器统一判断命令接受条件；UI 反馈时效只用于显示、初始化和实测重置 |
| RViz pending 必须收到终态 result 才能解除 | result 是有界、非持久事件流，丢失回执可使界面永久无法发送 | 删除 pending 门闩；结果只显示，运动中的新目标由控制器拒绝 |
| 30 mm 净空才允许 ENABLE、HOLD、故障确认 | 固定模型包络无法区分正常安装贴合与需要阻止的碰撞 | 几何距离不参与状态切换 |
| 8 mm 净空故障、30 mm 预警停止 | 缺少本机贴合姿态和几何误差的验证依据；单臂简化几何不代表整机真实接触状态 | 删除这两种几何停止条件，保留距离诊断 |
| 有限路径额外增加 10 mm 净空 | 在 8 mm 参数之外叠加了隐藏门槛 | 删除几何路径拒绝逻辑 |
| 制动前瞻的几何膨胀、采样和耗时预算 | 正常贴合也会导致制动验证失败；曾出现预算超时引发误停 | 制动前瞻仅验证关节位置极值，不再用净空拦截 |
| 关闭几何保护后仍校验几何参数、占用 0.5 ms 检查预算 | 已不执行的功能仍能阻止启动 | 删除几何保护开关、阈值和预算字段；接收预算只需小于周期 |
| 一次控制计算超过周期即 Fault 并切断输出 | 单次主机计算或调度抖动不等于测量已失效，直接被动输出也不是受控制动 | 计算超期只增加 overruns；失效反馈及超过反馈期限的控制间隔仍 Fault |
| Kp/Kd、阻抗刚度/阻尼写死的额外数值上限 | 没有对应本机辨识或硬件额定值；与可配置增益及输出力矩约束重复 | 保留有限正值要求、阻抗增益平滑和力矩幅值/变化率限制，默认增益不变 |
| 控制周期被限定在 1～20 ms | 真正的算法前提是有限正周期及超时/收发预算关系 | 删除固定范围，保留关系检查；默认 4 ms 不变 |
| ROS 状态发布率不得超过 250 Hz | 状态发布率不等于执行速度，固定上限不是硬件运动边界 | 只要求有限正值，默认 100 Hz 不变 |
| 只写不读的 stop_latched、resume_waiting、未使用模型配置副本和距离速度界接口 | 没有影响行为，只增加状态和维护负担 | 删除 |

几何诊断仍依赖模型数据，其合法性校验与算法数值错误处理保留；“诊断”表示不根据距离值干预运动，不表示忽略无效模型或数值异常。`collision_distance/pair` 字段继续发布，兼容现有状态订阅者。当前控制器没有几何碰撞阻止能力，也没有双臂互碰或环境绕障能力。

旧的 collision_check_enabled、collision_margin、collision_warning、validation_budget、lookahead_budget、max_collision_samples 和 send_on_release 已从源码/配置删除，不存在通过重新设参数启用旧拦截的路径。使用原生 Config 的调用方需要同步移除这些成员；ROS YAML 中的旧键不会再被读取。

## 保留及理由

| 约束 | 保留理由 |
| --- | --- |
| URDF 关节位置限位、整段多项式极值验证 | 终点合法并不能保证中间不越过机械边界 |
| 速度、加速度、jerk 及可制动的关节路径 | 限制运动变化并使停止轨迹留在关节范围内 |
| 输出力矩与变化率、URDF effort 上限 | 对实际执行输出形成直接约束 |
| 反馈时龄、数值、关节位置与速度、电机温度/错误、通信失败检查 | 控制依赖真实且有效的测量，错误数据不能继续驱动 |
| UDP 来源、长度、协议启用时的 CRC、接收积压处理 | 拒绝错误或旧报文，避免错误测量被当作新反馈 |
| 时间戳、坐标系、单位四元数、外部配置维度与有限性 | 是跨进程/原生调用的输入契约，防止错误坐标、NaN 和不合法参数进入计算 |
| 规划前后状态版本校验 | STOP/DISABLE 或新状态发生后，旧的并行规划不能再启动 |
| Disabled 首目标的静止和实测起点检查 | 从未知零参考或正在被外力移动的位置起步会造成参考跳变 |
| 运动中不接受抢占；Fault/AwaitResume 需处理 | 当前有限轨迹以静止起点构造，直接抢占会破坏连续性；停止指令应有持续效果 |
| 流式超时、会话和序号 | 生产者消失时停止，避免旧缓存或停止前的消息重新驱动 |
| 到达实测容差和稳定时间、超时失败 | 不能仅凭参考轨迹播放完就报告实际到达 |
| 启动时不自行建立保持输出 | 启动进程没有给出运动目标；现在明确目标本身即可使能，无需额外操作 |
| 标定逐臂确认、静止与零位验证、独占端口 | 标定修改 MCU 零点，不同于普通运动目标；错误标定会影响之后的所有计算 |
| 底盘速度/加速度限制、cmd_vel 超时、键盘释放超时 | 分别约束运动幅度、发布者断联、键盘节点仍活着但用户已停止按键，故障来源不同 |
| 云台串口接收超时、底盘电池/驱动故障指示 | 前者防止通信无限阻塞，后者是状态报告，没有发现需要删除的运动准入门槛 |

## 验证

回归覆盖贴合初始姿态、首条有限目标、非法首目标保持被动、旧反馈与运动中起点拒绝、模型障碍仅诊断、关节制动边界、力矩及运动限制、电机故障、流式超时、受控停止和正常退出。

使用临时目录安装 Pinocchio 4.0 测试依赖，不修改系统环境或降低项目依赖版本。原生测试使用内存反馈与 UDP 回环，Python 测试使用 ROS API 替身及离线模型展开；不启动真实双臂控制器、不执行真机运动或零点标定。这些结果不能替代部署后的真实闭环验证。

本次验证结果：

- Pinocchio 4.0、Ruckig 0.9.2 下原生构建通过。
- arm_core、reference_geometry、runtime_timing、timed_trajectory、cartesian_path、prepared_motion、motion_contract 七组通过。
- mcu_udp_loopback、dual_arm_calibration 两组通过；后者包含 23 项模拟标定检查。
- RViz 发送节点 12 项、启动配置 10 项、模型契约 5 项离线检查通过，共 27 项。
- 本次改动的差异格式检查通过。工作区原有 SDK_ALGORITHMS.md 的修改未触碰。

本机提供 ROS 2 Humble，没有 ROS 1 构建环境，因此本次使用 Z1_BUILD_ROS=OFF 构建控制内核；ROS 1 适配节点与真实 RViz 的完整构建、交互及真机闭环未验证。
