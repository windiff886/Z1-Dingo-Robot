# Z1 SDK 性能、控制效果与先进开源实现对比

审查日期：2026-10-23；代码基线：`af38180a2a0a0f2816f6a02943ac66958311d057`。第 1–6 节评价改动前基线，关注跟踪、响应、运动连续性、规划质量和计算效率；保护机制只讨论对这些指标的作用与代价。第 7 节记录第一轮实现，第 8 节记录 500 Hz 升级后的审查，第 9 节记录随后完成的定时执行、MoveL 和连续过点。

## 1. 结论

**算法库选型现代，连续参考生成和任务空间运动能力明显落后于所研究的先进开源实现；现阶段的主要瓶颈不是 RNEA 算力或控制周期。部分保守的在线几何检查已经限制柔顺效果和运动效率。**

| 维度 | 判断 | 改进价值 |
| --- | --- | --- |
| Pinocchio / Ruckig / Coal | 继续沿用，不能仅因算法年代否定 | 高性能基础已具备，重点在组合方式 |
| 位置计算力矩控制 | 有效基线，无证据表明必须换成 MPC/学习控制 | 先修正参考、补偿模型和实测调参 |
| 连续目标跟踪 | 主要短板，离线实测明显滞后 | 时间轨迹、速度/加速度信息和预测 |
| 笛卡尔跟踪 | 固定阻尼 DLS + 误差追赶 + 关节平滑，响应偏慢 | 任务空间前馈、合理权重和必要的约束求解 |
| 阻抗效果 | 基础力矩公式合理，偏差检查限制柔顺 | 模式相关几何处理、动态参考与增益 |
| 点到点轨迹 | jerk 受限生成是成熟选择 | 连续过点、时间约束和工具空间路径 |
| 绕障与动力学规划 | 有检查、无搜索/优化，与 cuRobo 有明确能力差距 | 有自主避障任务时引入规划层 |
| 250 Hz / 1 kHz | 本次仿真中提频未改善主要误差 | 先改参考与计算负担，再验证硬件提频收益 |

这里评价的是已实现能力和观测效果，不是全部工业任务的排名。没有对外部框架做同硬件、同 Z1 模型的横向性能实验。

### 2.1 franky：主要差距在参考和运动管理

[WaypointMotion](https://github.com/TimSchneider42/franky/blob/f88f0e9b8f598d7c537b4e727e4411e67c95e017/include/franky/motion/waypoint_motion.hpp) 复用 Ruckig 更新接口，处理实际周期与路点接续；[CartesianWaypointMotion](https://github.com/TimSchneider42/franky/blob/f88f0e9b8f598d7c537b4e727e4411e67c95e017/src/motion/cartesian_waypoint_motion.cpp) 带目标速度，转换参考坐标时处理速度与加速度。该实现也承认旋转速度处理存在近似，不能因此宣称任意大旋转都有严格保证。

[动态阻抗参考](https://github.com/TimSchneider42/franky/blob/f88f0e9b8f598d7c537b4e727e4411e67c95e017/include/franky/motion/cartesian_impedance_base.hpp) 包含位姿、可选 twist 和加速度；[阻抗实现](https://github.com/TimSchneider42/franky/blob/f88f0e9b8f598d7c537b4e727e4411e67c95e017/src/motion/cartesian_impedance_base.cpp) 使用速度误差、可选任务惯量加速度前馈、在线增益平滑和可选摩擦补偿。

Z1 已有由内部参考计算的速度误差项，不能说完全没有阻抗速度前馈；差距在上游动态参考、加速度前馈和更灵活的增益/参考策略。

Franka 是七轴，Z1 是六轴。一般满秩六轴完整位姿任务没有多余自由度，不能直接照搬七轴零空间姿态与可操作度任务。franky 的笛卡尔命令也依赖 Franka 内部 IK 和控制器，不能全部计作上层库能力。

### 2.2 基础阻抗不需要为“先进”而复杂化

[libfranka 官方示例](https://github.com/frankarobotics/libfranka/blob/e88d08f64cbf842b8f53c0b551963684064038d6/examples/cartesian_impedance_control.cpp) 也是 J 转置弹簧阻尼加补偿，明确不做惯量整形。

因此修正上一版的侧重点：没有 MPC、被动性管理或期望惯量整形，不应直接扣先进性分。先看实际跟踪、接触响应与任务是否需要这些能力。不同硬件承担的重力/摩擦补偿不同，不能照搬公式和增益。

### 2.3 Mink / PyRoki：约束与任务共同求解

[Mink QP](https://github.com/kevinzakka/mink/blob/ae6759602593113ed7e5431ac7c65726ea27dc29/src/mink/solve_ik.py) 将加权任务、限位和可选等式约束组合；[局部避碰](https://github.com/kevinzakka/mink/blob/ae6759602593113ed7e5431ac7c65726ea27dc29/src/mink/limits/collision_avoidance_limit.py) 使用几何对接近方向的雅可比约束每步距离变化，先筛远处几何对。其双臂 ALOHA 示例采用 200 Hz IK 循环，不等于驱动器或力矩内环仅需 200 Hz。

[PyRoki 基础 IK](https://github.com/chungmin99/pyroki/blob/388e43e1fc0d0ee382968d3dd72970fd62a0450c/examples/pyroki_snippets/_solve_ik.py) 使用位置/姿态权重和信赖域；[碰撞 IK](https://github.com/chungmin99/pyroki/blob/388e43e1fc0d0ee382968d3dd72970fd62a0450c/examples/pyroki_snippets/_solve_ik_with_collision.py) 显式加入约束和代价。

对 Z1 的价值是更平滑地接近边界、提高困难目标求解质量。但简单可达、远离约束的六轴单目标任务中，QP 不天然比小矩阵 DLS 更准或更快。先改参考和目标表达，在限位、避碰或多任务确实影响效果时增加约束求解。

### 2.4 cuRobo：规划能力差距具体存在

[MotionPlanner](https://github.com/NVlabs/curobo/blob/78fd485fa82d9b9a063fb4985e371814587e666a/curobo/_src/motion/motion_planner.py) 组合多种子 IK、图规划播种和轨迹优化；[TrajOptSolver](https://github.com/NVlabs/curobo/blob/78fd485fa82d9b9a063fb4985e371814587e666a/curobo/_src/solver/solver_trajopt.py) 细化时间步并检查插值轨迹，不只是找到端点再执行。

cuRoboV2 的动力学约束 B 样条优化有公开技术报告支持，但论文成绩不等于 Z1 上的收益。[论文](https://arxiv.org/abs/2603.05493)

当前 Coal 距离检查和 Ruckig 点到点生成不会主动寻找另一条路线。自主绕障任务下是能力缺失；普通遥操作未必需要整个 GPU 规划栈。

### 2.5 Diffusion Policy：简单执行器也可支撑先进任务

[位姿插值器](https://github.com/real-stanford/diffusion_policy/blob/5ba07ac6661db573af695b419a7947ecb704690f/diffusion_policy/common/pose_trajectory_interpolator.py) 使用平移插值、旋转 Slerp，管理路点时间与速度；[RTDE 执行进程](https://github.com/real-stanford/diffusion_policy/blob/5ba07ac6661db573af695b419a7947ecb704690f/diffusion_policy/real_world/rtde_interpolation_controller.py) 周期性采样时间轨迹，并从已有参考接续。

它不是比 Ruckig 更完整的 jerk 受限生成器，也不自己实现 UR 底层伺服。这里的启示是：时间一致、参考连续和职责划分往往比每层都使用复杂控制更关键。

## 3. 本机离线实验

新增 [performance_audit](tools/performance_audit/README.md) 复现本节；[原始输出](tools/performance_audit/RESULTS_2026-10-23.txt) 已保留。只使用当前 z1_core、Pinocchio 仿真与合成反馈，不接硬件、不运行 ROS。

环境：Intel i9-13900HX，Linux x86_64，GCC 11.4，Release；Pinocchio 4.0.0、Coal 3.0.3、Ruckig 0.9.2。控制器与被控对象使用相同模型；无真实摩擦、噪声或接触。计算耗时是本机观测，不是实时上界。

### 3.1 提频没有解决流式跟踪滞后

输入 joint1 幅值 0.03 rad、0.25/0.5 Hz 正弦目标，其余目标关节固定，目标 50 Hz 更新。保持 4 秒后运动 12 秒，忽略运动前 4 秒。最大目标速度约 0.094 rad/s、加速度 0.296 rad/s²、jerk 0.930 rad/s³，均低于配置限制。

| 目标频率 | 仿真控制步频 | joint1 RMS 误差 | 基频相位对应滞后 |
| --- | --- | --- | --- |
| 0.25 Hz | 250 Hz | 2.784 mrad | 83.35 ms |
| 0.25 Hz | 1000 Hz | 2.859 mrad | 85.58 ms |
| 0.5 Hz | 250 Hz | 7.521 mrad | 113.84 ms |
| 0.5 Hz | 1000 Hz | 7.711 mrad | 116.76 ms |

这是固定步长仿真，不含通信与 Linux 调度；滞后来自正弦响应拟合，不是网络延迟。只能说明此轨迹的主要误差未因提频改善，不能泛化成提高频率会普遍恶化效果。

0.5 Hz、250 Hz 一组的误差分解：

| 链路 | joint1 RMS 误差 |
| --- | --- |
| 连续理想目标 → 生成参考 | 7.478 mrad |
| 生成参考 → 仿真实测 | 0.053 mrad |
| 连续理想目标 → 仿真实测 | 7.521 mrad |

主要误差发生在参考生成之前/之中，不能归咎于 RNEA 或伺服计算慢。

`controller.cpp:563` 每次只把位置当作最终静止目标，没有上游速度/加速度信息。目标不断移动，生成器仍持续求到当前目标并停下的轨迹，形成追赶滞后。Ruckig 官方也解释了这种现象，提供预测跟踪接口；专用接口属于 Pro，不能误写成当前项目已经具备的开源功能。[Ruckig 教程](https://docs.ruckig.com/tutorial.html)

诊断对照使用连续解析 q/dq/ddq，保留相同 RNEA、增益、力矩限制与仿真，0.5 Hz 下 joint1 RMS 约 0.033 mrad。该对照获得更多参考信息，绕过生产参考生成与几何状态机，仅用于定位瓶颈，不能宣传为已实现升级的收益。

### 3.2 位姿流进一步增加低通效果

将同一目标关节轨迹经 FK 转为完整 TCP 位姿，50 Hz 输入 PoseStream，250 Hz 仿真执行：

| 目标频率 | TCP 平移 RMS | TCP 旋转 RMS |
| --- | --- | --- |
| 0.25 Hz | 1.207 mm | 10.10 mrad，约 0.58° |
| 0.5 Hz | 1.895 mm | 16.09 mrad，约 0.92° |

这是小幅局部目标，不是全工作空间误差统计。

`model.cpp:137` 以位置误差乘 4、姿态误差乘 3 生成速度，经固定阻尼 DLS 后再由 Ruckig 平滑。没有目标 twist 前馈，误差追赶本身就是低通；大误差时还有 0.12 m/s、0.5 rad/s 的任务速度上限。Impedance 的 speed=0.5 把饱和上限减半，不会把小误差反馈增益减半。

建议采用“目标 twist + 位姿误差校正”，让时间插值、约束 IK 和后续平滑共享一致参考。检查最终 TCP 轮廓和响应，避免只提高 IK 增益或在每层叠加平滑。

### 3.3 计算主要花在多次几何查询

微基准预热 100 次，测量 3000 次：

| 操作 | 本次中位耗时 |
| --- | --- |
| FK | 0.36 μs |
| 雅可比 | 0.46 μs |
| RNEA | 0.67 μs |
| 差分 IK | 0.87 μs |
| 整臂最小距离查询 | 12.92 μs |

0.5 Hz JointStream 的 250 Hz 仿真控制步中位约 216 μs、P99 约 283 μs；每步平均 12.2 次整臂距离查询，查询累计时间约占控制计算的 98%。统计不含仿真积分、外部统计或 MCU 收发，计时包装也有少量开销。

当前没有证据把重点放在替换 RNEA、小矩阵求解或增加 GPU。应先减少重复整臂查询、远处几何对查询和每步全制动路径采样。这个占比不是“整个系统 98% 都是保护逻辑”，也不说明其他校验都昂贵。

### 3.4 保守偏差包络限制阻抗效果

建立 Impedance 平衡参考，仅给 joint1 合成反馈增加 0.01 rad，其余反馈不变：

- 最小几何间距前后均约 34.52 mm。
- TCP 平移变化约 1.18 mm，关节偏移约 0.57°。
- 模式退出到 AwaitResume，原因是无法保持制动路径的间距条件。

这是合成反馈测试，不是接触实验，但说明实际几何间距未变时，小幅偏离平衡也可能结束柔顺模式。

根源在 `controller.cpp:625`：

```text
误差膨胀距离 = 2 × geometry_radius_bound × Σ|q_measured - q_reference|
默认 geometry_radius_bound = 1.5 m
```

0.01 rad 单轴偏差统一膨胀成 30 mm，再加 8 mm 基础余量，超过此姿态约 34.5 mm 最小间距。它未利用该偏差对当前最近几何对的实际影响。

该界有保守建模动机，但当前形式对阻抗有明确效果代价。借鉴 Mink 的几何对接近方向和局部雅可比，按模式区分参考偏差意义，比叠加全局停止阈值更有价值。局部线性约束仍需匹配实际动力学和离散步长，不是任意速度的碰撞保证。

## 4. 对控制与运动生成的判断

当前 `controller.cpp:701` 以 `ddq_ref + Kp*e + Kd*de` 经 RNEA 生成力矩，已经包含参考速度与加速度前馈，不能称为只有位置 PD。

默认 Kp 对应的 0.71–1.42 Hz 是理想误差动力学自然频率，**不是可跟踪轨迹的频率上限**。准确前馈可以帮助跟踪更快的可行轨迹；上一版依据这个数值推测控制性能的比重应降低。

真机先比较模型/负载误差、低速摩擦与反转、饱和比例和参考到实测的幅频/相频响应。只有这些结果说明经典控制不足，再考虑鲁棒项、惯量整形或 MPC。

Ruckig 点到点生成适合继续沿用；动态目标和已有时间轨迹应有不同处理。建议原生 API 支持可选 q/dq/ddq 或 pose/twist/acceleration，以及一小段带时间的未来路点。当前 JointStream 已维护内部参考连续性，这是正确基础，应保留，不能反复从滞后的实测值重启插值。

现有 poseGoal 是一次 IK 后的关节运动，不是工具空间直线。优先补局部笛卡尔路径和连续过点；圆弧、工艺恒速与全局绕障按任务增加，不把所有工业指令都设为首期门槛。

阻抗方面，对角 K/D 足以作为起点。比立即增加完整六维矩阵更优先的是：避免预期柔顺偏差触发普通跟踪偏差停止；支持动态参考；允许运动中平滑调增益。完整矩阵、加速度前馈和摩擦补偿按任务验证收益。

## 5. 哪些保护必要，哪些过重

**先进工作保留基本约束，但倾向于低开销边界处理、可配置求解约束和连续控制作用；不能从外层代码较短推断底层硬件没有保护。**

| 内容 | 源码依据 | 对当前项目的判断 |
| --- | --- | --- |
| v/a/jerk 约束 | franky 使用 Ruckig 与可调整动态限制 | 保留：直接决定平滑性和可执行速度 |
| 力矩变化率限制 | franky 的 saturateTorqueRate | 保留，避免限值过小不必要地牺牲响应 |
| 位姿/增益/有限数校验 | franky 在目标和增益写入边界验证 | 保留必要边界校验，避免重复昂贵转换；不是主要计算瓶颈 |
| 关节和碰撞约束 | Mink / PyRoki 将任务与约束共同求解 | 按场景配置，优先连续限速或改变允许运动，减少多余停止 |
| 全局半径 × 总关节误差包络 | 当前 Z1 的特定实现选择 | 应重做，已复现小幅偏差导致退出柔顺模式 |
| 每周期全制动路径采样 | 当前 Z1 的执行结构，不是这些运动层的统一要求 | 应评估分层、缓存和局部替代，不能无替代直接删除 |
| 正常更新需要重建运动/显式恢复 | franky 有持续 TrackingMotion，Diffusion Policy 有持续时间插值 | 不应成为正常连续更新默认流程，异常恢复与正常运动分开 |
| 随机会话、额外审计状态和恢复协议扩展 | 不是这些运动层统一的性能优化方法 | 本次不扩展，不以数量衡量先进性 |

franky 也使用 mutex，并设置优先级继承，不是把完全无锁当作先进条件；动态阻抗参考另用三缓冲。应按阻塞与抖动选择机制。[运动交接](https://github.com/TimSchneider42/franky/blob/f88f0e9b8f598d7c537b4e727e4411e67c95e017/src/motion/motion_generator.cpp)、[实时 mutex](https://github.com/TimSchneider42/franky/blob/f88f0e9b8f598d7c537b4e727e4411e67c95e017/include/franky/rt_mutex.hpp)、[参考缓冲](https://github.com/TimSchneider42/franky/blob/f88f0e9b8f598d7c537b4e727e4411e67c95e017/include/franky/motion/cartesian_impedance_tracking_motion.hpp)

Franka/UR 应用层精简也依赖内部控制器的执行职责。Z1 当前由主机输出力矩，反馈时效与输出边界不能直接去掉。构造时的模型指纹不占周期计算时间，也没有必要为追求性能优先删除。

上轮的 STOP 队列问题仍是缺陷，但不能证明控制效果或算法不先进，本版不再把这类可靠性清单作为评估主体。

## 6. ROS 边界与升级顺序

保留用户目标：Pinocchio、Ruckig、Coal、原生运动 API 和 MCU 通信属于 SDK；ROS 只传递目标与状态，不引入 MoveIt 作为必需组件。本次跟踪问题在无 ROS 仿真中已经出现，更换消息中间件不会自动消除它。

| 顺序 | 建议工作 | 评价收益 |
| --- | --- | --- |
| 1 | 时间轨迹/动态参考，修正纯位置追赶 | 相同目标、限制与增益下的相位、RMS、峰值误差和连续性 |
| 2 | 阻抗的几何偏差处理，降低全局保守性 | 相同实际几何下允许预期柔顺位移，减少多余退出 |
| 3 | 几何粗筛、活动几何对、减少整臂查询和全段重算 | 控制步耗时、查询数与运动中断率，保留同等任务约束 |
| 4 | twist 前馈、合理权重，按需引入约束 IK | TCP 响应、轮廓误差、限位附近跟踪与目标成功率 |
| 5 | 真机模型/负载/摩擦与增益，比较 250/500/1000 Hz | 实际精度、响应和力矩代价；先确认 MCU 能力 |
| 6 | 按需绕障、动力学优化、MPC 或 GPU | 同场景成功率、规划耗时、可执行性和任务完成时间 |

这些优先级来自源码阅读和基线实验，不能推出外部项目在 Z1 上必然更快。用户批准后的实现如下。

## 7. 已实施的性能升级

第一轮继续沿用 Pinocchio、Ruckig、Coal 与原有计算力矩控制；当时保持默认 250 Hz，没有引入 MoveIt、ros_control、MPC、GPU 或新的中间件。当前默认频率已在第二轮提升为 500 Hz，见第 8 节。

1. **时间参考和动态前馈。** 新增原生 `JointReference` / `CartesianReference` 与 ROS 对应消息。32 点时间线支持短时未来路点、在线替换、三次/五次 Hermite 插值和有界外推；SO(3) 插值正确映射角速度/角加速度。原纯位置接口自动估计导数。关节动态参考进入 Ruckig 的位置/速度/加速度目标；位姿流使用目标 twist 加误差反馈，DLS 在小奇异值处增加阻尼。
2. **阻抗参考与增益。** 平衡位姿和速度直接来自笛卡尔时间参考，关节 IK/Ruckig 参考用于运动与几何检查，避免将两者等同。Holding 和 Impedance 都可设置 K/D；阻抗中按默认 100 ms 时间常数平滑生效。仍为基础 J 转置弹簧阻尼加原有动力学补偿，没有加入任务惯量整形或接触力控制。
3. **几何计算与偏差包络。** 缓存相同 q 的距离、复用固定几何，先查上一最近对，再用 AABB 下界筛远处对。重叠 AABB 不用于剪除负穿透距离。按几何对及关节推导运动范围，共同祖先的刚体运动不膨胀自碰撞距离；替换统一的全局半径误差膨胀。轨迹自适应采样也使用该运动界，保留原有路径与制动检查。
4. **配套修正。** STOP 不再因普通操作队列已满而丢失；执行的停止轨迹也进行检查。没有扩展控制权、审计或恢复协议。

## 8. 500 Hz 升级后的实现及进一步审查

**当前默认原生控制周期为 2 ms。本机测试场景的算法计算耗时远小于这一周期；继续提高任务效果，优先级高于继续把平均频率推到 1 kHz。** ROS 仍只负责输入和状态传输，状态发布保持 100 Hz，未引入 MoveIt。以下结论来自当前实现、独立仿真及固定提交的开源源码对照，不表示已在用户的 i7-13700H 或实际 Z1 上完成验证。

### 8.1 本轮已完成的优化

- **周期与时间一致性：** SDK、MCU 适配和 YAML 默认统一为 500 Hz；默认接收预算 1 ms、在线几何检查预算 0.5 ms。Runtime 采用单调时钟绝对节拍，超过周期后跳过已过期的槽位，避免补发连续旧周期。流式 Ruckig 参考按实际时间间隔推进；仅在与标称周期相差小于 1 ns 时消除时间戳相减的浮点噪声，实际周期统计不被改写。
- **调度与观测：** 可选控制线程 CPU 亲和性和 SCHED_FIFO 优先级；默认保持系统设置。新增周期数、跳槽、收发耗时、唤醒迟到和调度设置结果。不能用平均 Hz 代替尾部延迟或真实 MCU 新反馈率。
- **几何热路径：** 新增 `ClearanceSample`，返回生命周期绑定 Model 的名称视图；原拥有字符串的 `Clearance` 接口仍可用。每个几何对持久保存 `coal::ComputeDistance`，每次仍使用新的 DefaultGuess 请求与结果，未改距离容差、符号或 GJK 初值策略。静止参考不再因浮点噪声不断失效缓存。
- **运动学与 ROS：** FK 只更新需要的 TCP frame；差分和迭代 IK 共用一次 FK/Jacobian 计算。ROS 流式订阅启用 TCP_NODELAY，复用 JointState 的数组与名字。Status 增加时序字段，部署时需重编译消息及订阅端。

### 8.2 500 Hz 的证据与边界

独立墙钟探针在 Intel i9-13900HX、Linux 6.8.0-138-generic 上，每个频率运行 10 秒，未设置 FIFO 或绑核。500 Hz 档平均 499.994 Hz，周期 P99 为 2.185 ms、最大 2.250 ms，跳槽计数 0；50 Hz 生产者的 500 次动态参考均接受。[完整调度输出](tools/performance_audit/RESULTS_RUNTIME_2026-10-23.txt)

ROS 双进程 topic 仿真中观测默认主机反馈序号约 499.7 Hz；原生四项回归及 ROS 集成通过。反馈序号表示主机仿真/有效收包，不等同于固件内部采样频率。墙钟探针的仿真植物仍固定步长积分，而参考按实际 dt 推进，因此只用它判断调度，不用它证明真实时间的跟踪精度或提频收益。十秒记录也不是长期最坏延迟保证。

固定步长效果实验中，50 Hz 上游、0.5 Hz/0.03 rad 正弦在 500 Hz 执行时，原生 q/dq/ddq 动态参考 RMS 为 0.0933 mrad，提前 40 ms 的参考为 0.0897 mrad；本轮计算优化前后结果相同。纯位置兼容接口为 4.301 mrad，基频滞后 57.49 ms，幅值比 1.0559。两类接口拥有的信息不同，不用它们的差值宣称单一优化收益。即使提频到 1 kHz，此纯位置样例仍为 4.468 mrad；参考生成仍是更重要的效果瓶颈。[本轮前](tools/performance_audit/RESULTS_500_BEFORE_2026-10-23.txt)、[本轮后](tools/performance_audit/RESULTS_500_AFTER_2026-10-23.txt)

### 8.3 剩余优化按收益排序

| 优先级 | 具体空间 | 为什么值得做；如何评价 |
| --- | --- | --- |
| 1 | 区分在线目标追踪与已定时轨迹执行 | 当前带时间的 q/v/a 仍每周期作为 Ruckig 新目标，并带 30 ms 最短时长/前瞻。对已规划轨迹，这会再次改变时间和形状。增加原生的预校验、重定时和直接采样执行通道，再测轮廓误差、相位、导数连续性与限值；保留在线追踪用于未知未来目标。franky 的运动接续和 Diffusion Policy 的按时间采样值得参考。 |
| 2 | 原生笛卡尔直线、圆弧和连续过点 | 当前 poseGoal 是 IK 后关节运动，不保证 TCP 直线或工艺恒速。构建平移/SO(3) 路径与时间参数化、连续 IK 和转角融合，以 TCP 轮廓误差、速度均匀性和任务耗时评价，不需要 MoveIt。 |
| 3 | 模型、负载、摩擦与分轴动态限值 | 当前刚体 RNEA 没有辨识摩擦项，默认各轴 v/a/jerk 相同。实际负载和摩擦误差可能远大于微秒级计算差别。测低速反转、带载轨迹及力矩饱和后，再标定工具惯量、补偿与各轴限制；不能仅从 CPU 型号推出更大加速度可行。 |
| 4 | 有约束的局部 IK 与可配置任务权重 | 当前 DLS 后逐轴裁剪/终端限速会在限位或奇异附近改变任务方向；任务速度上限固定为 0.12 m/s、0.5 rad/s。参考 Mink/PyRoki 将任务和约束共同求解，比较困难姿态成功率、TCP 误差和耗时。六轴完整位姿任务不照搬七轴零空间控制。 |
| 5 | 收发流水线和第三方残余开销 | 当前顺序是发送上一周期输出→接收→计算→等待；闭源 IOUDP 只公开合并 sendRecv，无法通过调整 Runtime 调用顺序直接消除一周期输出延迟。独立协议实现可研究接收/计算/发送，但需先量实际链路收益。Coal 内部剩余分配可按剖析结果处理，避免为消灭计数而重写成熟算法。 |
| 6 | 按任务扩展阻抗与全局规划 | 阻抗仍为 J 转置 K/D 加动力学补偿，可按任务加入工具坐标系/完整增益矩阵与任务惯量加速度前馈。需要绕障时引入独立规划层、多种子与轨迹优化；4070 适合评估 cuRobo 等规划任务，不用于替换当前六轴小矩阵伺服。 |

官方 x86_64 动态库的静态反汇编还确认：`sendRecv` 总会调用 `LowLevelState::runFilter`，其中有两处每次构造向量的 `operator new`，即 500 Hz 下仅此路径就有约 1000 次分配/秒，虽然当前适配器读取原始 q/dq/tau。该路径未计入离线分配工具。本轮未修改二进制或绕过其 ABI；[固定 SHA-256 的反汇编证据](tools/performance_audit/VENDOR_HOTPATH_2026-10-23.txt)支持将它列为后续通信层优化点。

共享快照仍会在锁内复制静态模型指纹。它在 100 Hz 状态发布中的优先级较低；只有测得阻塞或尾延迟后，再缩短临界区或使用适合实时线程的锁。franky 本身也使用带优先级继承的 mutex，完全无锁并非先进性的必要条件。

本机依赖仍为 Ruckig 0.9.2，而审查当日[官方教程](https://docs.ruckig.com/tutorial.html)标注 0.19.7。可独立评估升级及边界行为/性能变化；版本差距本身不能证明当前轨迹效果差，也不能把新版本 Pro 功能当成本项目已有的开源能力。下一轮优先解决以上可测的任务与执行差距，再决定是否更换控制律或规划栈。

## 9. 已实施：定时轨迹、MoveL 与连续过点

本轮按第 8.3 节前两项推进：将在线目标追踪与完整定时计划分开，并增加原生工具直线及连续路径。原生周期仍为 500 Hz，ROS 只转换与传输消息，没有新增 MoveIt 或 ROS 规划依赖。

### 9.1 轨迹执行方式

新增 `JointTrajectory`，准备阶段生成 C2 五次 Hermite 多项式，使用导数根及分段极值检查关节位置、速度、加速度和 jerk。严格模式保持给定时间与显式导数，不可行则拒绝；可选全局时间伸缩保持几何路径并降低导数。执行阶段按单调时钟直接采样，不再进入流式 Ruckig 前瞻。

`Controller::trajectory` 适用于已定时的示教/策略动作块；`jointWaypoints` 自动安排时长和内部速度，支持同方向路点连续通过。首尾停止，复用原有到达判定、RNEA 前馈和受控停止。已有 JointStream/PoseStream 继续处理在线未知目标，有限 JointGoal/PoseGoal 也保留原有语义。该分工与 UR 的独立样条轨迹/伺服接口、franky 的带目标速度路点一致；它不要求把所有输入都改为一次性完整计划。

固定步长仿真中，4 秒 sin³ 轨迹由 201 个解析 q/v/a 路点构成。定时模式生成参考与理想信号的 q1 RMS 差约 3.14e-14 rad，说明该样例没有再次整形；仿真实测 q1 RMS 为 0.01455 mrad，控制 step 中位约 7.02 μs。既有 50 Hz/40 ms 未来流的参考和仿真实测 RMS 分别为 0.04742、0.04045 mrad，step 中位约 9.36 μs。两者未来信息量不同，结果只用于说明接口语义和本样例效果；不能宣传为对任意流式任务的固定改善倍数。[完整方法和原始数据](tools/performance_audit/README.md)

### 9.2 笛卡尔路径

新增 `moveL` / `linearWaypoints`：先构造直线平移与 SO(3) 最短旋转路径，离线连续分支 IK，拟合五次关节轨迹并全局重定时。准备阶段验证关节插值后的 FK 路径误差及任务速度，必要时加密；500 Hz 执行线程不做 IK。

多点零 blend 在路点停止；正 blend 在裁剪转角内使用 C2 曲线，允许运动连续通过。它不精确经过被圆滑的中间点，也不是圆弧 MoveC。半径使用平移与旋转的组合度量，见 [接口契约](INTERFACES.md)。原 `poseGoal` 保持终点 IK 后关节运动，调用方显式选择所需路径语义。

10.77 mm 直线样例中，准备约 0.175 ms，密集采样最大轮廓误差约 0.987 μm；这是软件 FK 对目标路径的误差，不是真机精度。默认 0.1 mm / 1 mrad 为每段 9 点 FK 数值验收阈值，不是连续区间的解析上界。测试另覆盖共同平移/旋转进度、纯旋转、非共轴旋转转角、限速及不可达目标。

**连续不等于更快。** 当前保持几何的全局重定时仍较保守：12 mm + 12 mm、4 mm 转角 blend 的例子，角点约 8.62 mm/s 连续通过，但完成时间 3.282 s，高于逐点停车的 2.892 s。局部转角的 jerk 峰使整条路径一起减速；下一步如需加工效率，应研究局部时间参数化，而非继续压低微秒级采样开销。[原始路径结果](tools/performance_audit/RESULTS_CARTESIAN_2026-10-23.txt)

### 9.3 执行与验证

所有新规划在调用线程与独立模型中准备，控制锁仅用于状态快照与安装计划。ROS 的有限规划使用独立单线程回调队列，避免多项 IK/拟合占满服务操作和在线参考的线程。新模式追加为 10/11，旧值不变；Status 提供实际计划时长与全局伸缩倍率，消息需重新构建。

独立 Release 构建和七项 CTest 通过；ROS 1 的 16 种消息和节点编译成功，最终双进程集成通过定时/重定时轨迹、连续关节路点、MoveL 以及原有流式与阻抗接口。定时控制器测试在不规则 dt 下与预生成样条逐次一致；2000 次轨迹采样的普通 C++ new/new[] 为零。未连接实际 Z1，未在用户的 i7-13700H 上运行；真实模型、摩擦、负载和 MCU 时延仍是下一步现场工作。
