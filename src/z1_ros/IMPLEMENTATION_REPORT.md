## 2. 旧链路删除

已删除 `z1_controller`、`z1_sdk`、`z1_hw`、两套 MoveIt 配置、`z1_examples`、`z1_rviz`、`unitree_ros` 和旧控制说明/启动文件。原描述网格及供整机描述使用的 xacro 常量迁入 `z1_description`。必要 MCU 头文件、许可证及 x86_64/aarch64 官方动态库集中保留在 `vendor/unitree`。

## 3. 实施中修正的契约

- 官方 `sendRecv()` 的布尔值不能证明收到新状态；通过真实套接字事件增加反馈序号。相同测量值的新报文仍是新反馈。
- V2 的状态字段直接从有效接收报文检查，避免公开温度数组被连接字段覆盖的问题；V1 缺失的诊断不伪造为可用。
- 有限轨迹检查整段与关节解析极值；实际生成的停止轨迹也检查。Ruckig 0.9.2 零时长段未初始化的中间值不参与极值判断，静止流式目标不会因此被错误拒绝。
- 在线检查加入参考步的运动包络、测量与参考偏差、候选参考的制动路径和查询预算。查询耗尽预算按失败处理。
- 流式目标保留源时间戳对应的剩余有效期；有效的稍早目标不会因控制线程并发推进而被全部拒绝。会话初值随机生成，停止/恢复更新会话，旧 token 和缓存不能恢复运动。
- 非有限测量、过期测量、超限速度及设备错误按无效反馈处理；ROS 的 `feedback_valid` 使用内核的完整判断，避免无效测量被标成有效并发布旧 TCP。
- 主关节 MCU Kp/Kd 为零，位置控制由上位机计算力矩，动力学补偿只计入一次。主臂力矩限幅及限变化率；阻抗停止清除旧目标并生成制动参考。
- ROS 节点先完成模型/参数验证，再初始化通信。正常退出尝试有时限的受控停止及最终被动报文，不声称获得固件停止确认。
- 安装后的可执行程序和 MCU 适配库设置运行库搜索路径，官方库在构建及实际加载时检查 SHA-256。

## 6. 真机待验收

UDP 启动默认 `hardware_validated=false`，明确验收后才由现场人员启用。以下无法通过当前离线环境完成：

1. 确认固件版本、原始 q/dq/tau 的单位与轴方向、主关节零增益/力矩执行语义，以及设备是否已经进行其他补偿。
2. 测量工具/夹爪/负载质量、质心与惯性，核实 TCP 及完整张合包络。默认工具 0.25 kg 和简化碰撞几何为待核实的工程初值。
3. 按实际安装填写基座重力、支架/底盘 `fixed_boxes`，审查碰撞排除对和半径界。默认固定结构为空，不提供未建模的支架防护。
4. 在机器人上的 i7-13700H 部署机验证默认 500 Hz 收发、新反馈率、时延、最坏计算耗时及调度抖动，并在相同任务和负载下与 250 Hz 比较跟踪及扰动响应；核实 MCU 的实际采样与执行节奏，按测量结果调整周期和预算。
5. 逐步调试位置控制及阻抗增益、力矩限制，测量跟踪误差、实测停止距离、输入/反馈中断及正常退出的设备行为。
6. 核实 MCU 失联看门狗、被动命令、机械制动和硬件急停。反馈失效时软件不能保证可靠的闭环减速。

## 8. 2026-10-23 默认 500 Hz 与执行路径优化

默认原生周期从 4 ms 改为 2 ms；原生 `Config`、`McuConfig`、ROS 参数默认值和 `control.yaml` 保持一致。默认 MCU 接收预算为 1 ms，在线轨迹检查预算为 0.5 ms；ROS UDP 入口检查两项预算之和小于控制周期。预算是单项等待或检查上限，并非完整循环耗时的保证；其余计算和系统调度仍须计入现场测量。ROS 状态发布保持默认 100 Hz，未把 ROS 消息发布放入 500 Hz 原生控制线程。

执行循环保持绝对时间网格。交换或唤醒延误后跳过已经过期的槽位，计入 `missed_control_slots`，避免连续补发过期周期；正常运行和退出时的受控停止共用该节拍。流式 Ruckig 参考按相邻控制调用的实际 `dt` 推进，与有限轨迹的时间采样一致；小于 1 ns 的名义周期减法误差归一化，避免静止参考产生数值残余运动。收发仍沿用官方请求/响应链路：本轮发送上一轮输出，接收反馈后计算下一轮输出，未声称消除了这段流水线等待。

`RuntimeOptions` 支持只针对控制线程设置 CPU 亲和性和 `SCHED_FIFO` 优先级。默认 CPU 为 `-1`、优先级为 `0`，沿用操作系统调度；部署时应依据实际 CPU 拓扑选取允许的性能核。设置结果和 pthread 错误码可查询，不具备实时调度权限时仍能运行并报告未应用。新增统计包含循环数、过期槽数、当前/最大交换耗时和唤醒迟到。它们是宿主机的观测值；新 UDP 报文序号也不等于独立 MCU 采样时钟。

控制热路径改用 `clearanceSample`，通过模型生命周期内有效的字符串视图返回几何对名称，保留原有返回字符串的 `clearance` 接口。每个几何对持有独立的 Coal `ComputeDistance`，避免每次查询重复进行几何类型分派和初始化求解器对象；每次仍使用新的默认请求和结果，未启用跨查询初值复用。AABB 粗筛、带符号距离、缓存、逐几何对位移界及轨迹/制动路径检查继续保留。运动学计算只更新所需 TCP 帧，并在 IK 内复用同次雅可比计算得到的位姿。

ROS 状态发布复用 `JointState` 数组，连续参考订阅启用 `tcpNoDelay`。`Status.msg` 增加运行时统计和调度设置结果，消息 MD5 已改变；部署时必须重新编译 `z1_msgs`、节点及依赖它的订阅者，并更新 Python 消息环境。现有关节/位姿流消息及其会话语义保持兼容。

## 9. 2026-10-23 预计算轨迹、MoveL 与连续过点

执行入口现已区分两类需求：持续修订的目标流继续使用时间线、预测和在线 Ruckig；已经规划好的有限轨迹在提交线程准备，执行时按单调时钟直接采样，不再经过流式前瞻和第二次在线整形。原有 `joint_goal` / `pose_goal` 的行为保留；其中 `pose_goal` 仍是终点 IK 后的关节运动，需要指定 TCP 路径时使用新增接口。

| 原生接口 / ROS topic | 行为 |
| --- | --- |
| `Controller::trajectory` / `joint_trajectory` | 接收相对时间和 q/v/a；预计算分段五次 Hermite；默认保留时间及显式导数，超限拒绝；显式 `retime=true` 可全局放慢 |
| `Controller::jointWaypoints` / `joint_waypoints` | 自动补入当前参考、安排路点时间及受限内部速度；首尾停止，同方向内部路点通常连续通过 |
| `Controller::moveL` / 单点 `linear_path` | TCP 平移直线、SO(3) 最短旋转，使用共同路径进度；离线连续分支 IK 和关节样条拟合 |
| `Controller::linearWaypoints` / 多点 `linear_path` | 零 blend 半径逐点停车；正半径裁剪转角并 C2 圆滑连接，可处理纯旋转；不精确经过被裁剪的中间点 |

`JointTrajectory` 在准备阶段求分段多项式导数的根，验证完整区间的关节位置及 v/a/jerk 极值，而非只检查路点。省略内部速度时用受限相邻斜率估计，省略加速度时取零；节点两侧位置、速度和加速度连续。全局伸缩保持归一化多项式和关节路径形状，v/a/jerk 分别按倍率的一、二、三次方降低。位置越限和几何碰撞不能靠放慢修复。Controller 执行入口要求首尾静止，仍以实测到达及稳定时间判定成功。

笛卡尔路径使用独立规划模型完成离线 IK、有限差分导数、样条拟合和全局重定时，采样阶段不再求 IK。默认任务速度基准为平移 0.12 m/s、旋转 0.5 rad/s，再乘 `speed_scale`；关节约束需要时进一步放慢。默认平移拟合阈值 0.1 mm、旋转 1 mrad，每个关节样条段检查 9 个时间点，超差加密，最多 5 轮。这是模型参考的有限采样验收，不是连续区间的数学误差上界，也不代表真机定位精度。当前没有时间最优参数化或 MoveC 圆弧。

路径构造、拟合及全段几何检查在提交线程完成，不持有控制锁。ROS 为有限运动使用独立的单线程规划回调队列，普通回调线程处理操作和流式输入；STOP/DISABLE 会使仍在准备的旧计划失效。500 Hz 内核直接采样已接受路径，沿用原有计算力矩控制、在线几何检查和受控停止。

ROS 新增 `TrajectoryPoint`、`JointTrajectory`、`JointWaypoint`、`JointWaypoints`、`LinearPath` 五种消息，当前合计 16 种。模式新增 `JointTrajectory=10` 和 `CartesianPath=11`，旧值不变。`Status` 新增 `trajectory_duration`（秒）和 `trajectory_time_scale`。部署时需重新编译并 source 消息、节点及相关订阅端。字段和调用示例见 [INTERFACES.md](INTERFACES.md)。
